# ByHeart for VS Code 제품 요구사항

작성일: 2026-11-09 · 상태: 1차 초안(lean). 2026-11-09 실시간 WPM 표시 결정 반영. 근거는 [초기 탐색 문서](../discovery/2026-11-09-brainstorm-ideas.md)이며, 사용자 결정(탐색 문서 6절)을 반영했다. 확인되지 않은 것은 7.4에 가정으로 둔다.

## 1. 요약

ByHeart for VS Code는 **문장을 타이핑해서 외우는 VS Code 확장**이다. 외울 문장은 사용자 PC의 `~/.byheart` 폴더에 둔 `.byheart.json`·`.txt` 파일이며, 설치 직후에는 저작권이 만료된 인물의 명언이 기본 교재로 들어 있다. 웹앱 ByHeart에서 검증한 "힌트 → 타이핑 → 정답 비교" 흐름을 에디터 밖으로 나가지 않고 쓰게 하며, 마켓플레이스 공개를 목표로 한다.

## 3. 배경

웹앱 ByHeart는 『영어책 한 권 외워봤니?』를 회사 PC에서 한 대사씩 타이핑해 외우는 개인 도구다. 그런데 하루의 대부분을 VS Code 안에서 보내는 사용자에게 브라우저 탭을 여는 것은 작은 틈(빌드·테스트 대기)에 하기엔 전환 비용이 있다. 같은 틈을 노린 [Warm Up — Typing Test](https://marketplace.visualstudio.com/items?itemName=jeusto.warm-up-typing-test)는 설치 2만여 건으로 "에디터 안에서 타이핑 연습"에 수요가 있음을 보여 주지만, 측정하는 것은 속도(WPM)이지 기억이 아니다. 마켓플레이스에서 `byheart`는 비어 있고(2026-11-09 확인), `memorize` 검색 결과는 Anki 연동이나 스니펫 기억 도구라서 **타이핑으로 문장을 외우는** 확장은 없다.

## 4. 목표

**목표:** 사용자가 외우고 싶은 문장을 자기 파일로 가져와, 에디터를 떠나지 않고 날마다 짧게 타이핑 반복하게 한다.

핵심 결과(제안이며 수치는 실사용 후 조정):

| 핵심 결과 | 확인 방법 |
| --- | --- |
| KR1. 사용자 본인이 `.vsix` 설치 후 4주 동안 근무일의 60% 이상 하루 한 바퀴(챕터 하나) 이상 완료 | `~/.byheart/records/`의 완료 기록 |
| KR2. 공개 후 첫 3개월 안에 외부 사용자가 자기 `.txt`나 `.byheart.json`으로 연습한 사례 1건 이상 | 이슈·리뷰·메일 등 사용자 보고 |
| KR3. 공개 후 "파일을 못 읽는다"는 이슈를 받으면 다음 릴리스에서 해결 | GitHub 이슈 |

완료 기록을 암기 성공으로 해석하지 않는다. 웹앱과 같은 원칙이다.

## 5. 시장 세그먼트

세그먼트는 하는 일로 나눈다. 1차는 두 개까지만 본다.

- **S1. 에디터 안에서 영어 문장을 외우려는 개발자.** 사용자 본인이 첫 사례다. 외울 교재가 이미 `.byheart.json`으로 있거나, 영어 메일·문서에서 외우고 싶은 문장을 모아 둔다. 틈새 시간에 키보드만으로 반복하고 싶다.
- **S2. 외우고 싶은 글을 텍스트 파일로 갖고 있는 VS Code 사용자.** 명언·시·연설문·경전·외국어 문장 등. Anki 같은 카드 앱은 만들기가 번거롭고, 타이핑 연습 앱은 자기 글을 못 넣거나 속도만 잰다.

**제약:** 사용자 PC에서만 동작한다. 서버·계정·동기화·원격 측정이 없다. VS Code 데스크톱 전용이며 vscode.dev 같은 웹 환경은 지원하지 않는다. Remote-SSH·WSL에서도 확장은 로컬 머신에서 실행된다. 기본 교재는 공개 도메인 원문만 쓴다.

## 6. 가치 제안

### S1. 영어 문장을 외우려는 개발자

- **Who:** 하루 대부분을 VS Code에서 보내며 영어 문장을 외우고 싶은 개발자.
- **Why:** 외운 문장을 힌트 없이 재현하고 싶다. 문제는 연습을 "따로 시간 내서" 해야 해서 틈새 시간에는 손이 안 간다.
- **What before:** 브라우저 탭의 웹앱, 또는 책과 메모장. 탭 전환과 로그인 상태 확인이 번거롭고, 코딩 흐름이 끊긴다.
- **How:** 명령 팔레트의 `ByHeart: 연습 시작`(또는 사용자가 직접 건 단축키)으로 웹뷰에 입력칸 하나가 뜬다. 첫 단어와 둘째 단어 첫 글자만 힌트로 겹쳐 보이고, 타이핑하면 틀린 글자만 바로 표시된다. Enter로 정답을 비교하고 다음으로 넘어간다.
- **What after:** 빌드를 기다리는 1~2분에 카드 몇 장을 넘길 수 있다. 자기 `.byheart.json` 교재를 폴더에 복사만 하면 된다.
- **Alternatives:** 웹앱 ByHeart(브라우저), Warm Up(속도 측정, 자기 문장은 기록 제외). 에디터 안에서 **기억**을 연습한다는 점에서 우리를 고른다.

**가치 제안:** 코딩 중 틈새 시간에, 에디터를 떠나지 않고, 내 교재의 문장을 타이핑해 외운다.

### S2. 자기 글을 가진 VS Code 사용자

- **Who:** 외울 글을 이미 텍스트로 갖고 있는 VS Code 사용자.
- **Why:** 글을 통째로 외우고 싶다. 문제는 카드 앱은 카드를 일일이 만들어야 하고, 타이핑 앱은 내 글을 외우기 위한 구조가 없다.
- **What before:** Anki에 수동 입력, 또는 빈 문서에 외운 것을 치고 원문과 눈으로 대조.
- **How:** `.txt`를 `~/.byheart/books/<교재>/`에 넣으면 빈 줄로 나뉜 단락 하나가 카드 하나가 된다. 번역·해설까지 원하면 README의 AI 요청문으로 `.byheart.json`을 만든다.
- **What after:** 파일을 넣는 것만으로 교재가 생기고, 원문과 글자 단위로 비교해 어디가 틀렸는지 바로 안다.
- **Alternatives:** Anki, Memorize 계열 확장, 종이와 손. 설정 없이 자기 파일이 바로 교재가 된다는 점에서 우리를 고른다.

**가치 제안:** 파일을 폴더에 넣으면 그 글이 타이핑 암기 교재가 된다.

## 7. 해결책

### 7.1 핵심 흐름

```text
명령 `ByHeart: 연습 시작`  →  QuickPick: 교재 → 챕터  →  연습 웹뷰
┌─────────────────────────────────────────────┐
│ Day 1  3 / 12  [해석][연습][타이핑|힌트]     │
│                [미암기][이전]   [정답 확인] │  ← 헤더 고정 버튼. Enter = 정답 확인
│─────────────────────────────────────────────│
│ ┃ The o                                     │  ← 입력칸. 힌트가 반투명으로 겹침
│                                   34 WPM    │  ← 입력 시작 후 작게 표시
└─────────────────────────────────────────────┘
정답 확인 → 같은 자리에 원문 표시, 다른 글자는 밑줄 → Enter = 다음
마지막 카드 → 완료 요약(카드 수·정확도·평균 WPM) → [다음 챕터] (마지막 챕터는 [처음부터 반복])
```

입력 중 틀린 글자는 빨갛게, 해당 정답 단어는 그 아래 작게 보인다. 아직 쓰지 않은 부분은 공개하지 않는다. 정답 확인 화면은 대소문자·구두점 차이를 다른 색으로 구분한다. 한글 IME 조합 중에는 표시를 보류한다. 모두 웹앱의 현재 동작과 같다.

2026-11-11 사용자 결정: 상태바 항목을 두지 않는다. 공간을 차지하지 않도록 명령 팔레트로만 열고, 확장은 명령 실행이나 패널 복원 때만 켜진다. 자주 쓰면 사용자가 `byheart.start`에 단축키를 직접 건다(기본 단축키 기여는 하지 않는다). 액션 버튼은 카드 내용에 따라 움직이지 않도록 헤더에 고정한다.

2026-11-11 사용자 결정: `교재 폴더 열기` 명령을 `교재 편집`(Edit Books)으로 바꾼다. `~/.byheart/books`를 새 VS Code 창으로 열어 교재 파일을 에디터로 만들게 하고, 그 폴더에 안내 파일 `BYHEART-GUIDE.md`(실행 시 VS Code 언어)를 둔다. 안내 파일은 명령을 실행할 때 없을 때만 만들고 덮어쓰지 않으며, 이것이 확장이 사용자 교재 폴더에 쓰는 유일한 파일이다. 교재 선택 목록 맨 아래(내장 교재 하나뿐이면 챕터 목록 맨 아래)에도 같은 항목을 둔다.

2026-11-11 사용자 요청: 타이핑 모드에 확장 전용 **연습** 토글을 둔다. 켜면 반투명 힌트가 첫 단어·둘째 단어 첫 글자 대신 문장 전체가 되고, 외우기 전 문장을 보고 따라 칠 수 있다. 기본값은 꺼짐이며 해석 토글처럼 공통 설정으로 기억한다. 꺼져 있으면 힌트 규칙은 웹앱과 같다. 연습을 켜고 확인한 카드는 완료 요약과 기록의 정확도·평균 WPM에서 빼고 `practiceCards`로 따로 센다(구분 기록은 구현자 제안, 사용자가 진행을 승인).

### 7.2 1차 필수 기능

1. **타이핑 연습 웹뷰.** 위 흐름. 웹앱의 힌트·실시간 비교·정답 비교 규칙을 그대로 쓴다. VS Code 테마 색·폰트를 따른다. 패널을 숨겨도 입력을 유지한다.
2. **교재 폴더.** 기본 `~/.byheart/books/`(Windows `%USERPROFILE%\.byheart\books\`), 설정 `byheart.folder`로 변경. 하위 폴더 하나가 교재, 그 안의 파일 하나가 챕터. 파일명 숫자순 정렬. 파일이 바뀌면 다시 읽는다.
3. **`.byheart.json` 지원.** 웹앱 검수 스키마 그대로. 텍스트 챕터 최소 필드는 탐색 문서 6.3절. 음원 기반 파일도 열리며 시각은 무시. `kind: explanation`은 읽고 넘기는 설명 카드, `translation`은 해석 토글, `explanation`은 정답 확인 후 해설로 표시.
4. **`.txt` 지원.** 빈 줄로 구분한 단락 = 카드. 첫 줄 `# 제목`은 챕터 이름. 번역·해설 없음.
5. **기본 명언 교재.** 공개 도메인 원문 명언에 자체 작성 한국어 해석. 확장 패키지 안에 읽기 전용으로 포함. 출처 링크를 교재 파일에 보존.
6. **미암기 표시와 한 바퀴 완료.** 카드별 미암기 켜고 끄기, 완료 후 다음 챕터·반복. 자동 암기 판정·평점·복습 일정은 없다.
7. **실시간 WPM과 완료 요약.** 카드의 첫 글자를 입력한 순간부터 입력칸 구석에 WPM을 작게 표시하고, 정답 확인 시 멈춘다. 한 바퀴 완료 화면에 카드 수·정확도·평균 WPM을 한 줄로 보여 준다. 정확도는 정답 확인의 엄격 비교로 계산한다. 설정 `byheart.showWpm`으로 끌 수 있다. 개인 최고 기록·추이 그래프·카드 간 비교는 두지 않는다. 암기 타이핑의 WPM은 떠올리는 시간을 포함하므로 Warm Up 같은 속도 측정과 다르다는 점을 README에 적는다.
8. **기록 저장.** `~/.byheart/records/`에 교재·챕터별 JSON. 바퀴별 정확도·평균 WPM도 함께 남긴다. 임시 파일 작성 후 교체로 원자적으로 쓰고, 두 창이 동시에 쓸 때는 revision 비교로 덮어쓰기를 막는다. Settings Sync에 올리지 않는다.
9. **AI 교재 작성 가이드.** README에 복사용 요청문. 임의 텍스트를 `.byheart.json` 최소 스키마로 만들게 하며 UUID·빈 줄 금지·해설 서식(`- ` 불릿, `**굵게**`, `*이탤릭*`) 제약을 포함한다.
10. **공개 준비.** MIT 라이선스, 영문 README(한국어 병기), 128px PNG 아이콘, 네트워크 요청·원격 측정 없음 명시, `extensionKind: ["ui"]`, `.vsix` 로컬 설치로 먼저 검증.

### 7.3 기술

- 확장 호스트(Node.js)가 파일 읽기·기록 저장·QuickPick을 맡고, 웹뷰가 연습 UI를 맡는다. 메시지로 통신한다.
- 힌트·실시간 비교·정답 비교·강조 로직은 웹앱 저장소의 `src/lib/hints.ts`, `live-diff.ts`, `diff.ts`, `answer-diff.ts`, `emphasis.ts`, `sentences.ts`를 **복사해서** 쓴다(2026-11-09 사용자 결정). 이 파일들은 DOM·React 참조가 없는 순수 TypeScript임을 확인했다. 복사본에는 원본 커밋 해시를 적어 두고, 변경이 잦아지면 패키지 추출을 다시 검토한다. 웹앱의 `live-diff.worker.ts`를 웹뷰에서 Worker로 그대로 쓸 수 있는지는 설계에서 확인한다.
- Warm Up은 GPL-3.0이므로 코드를 가져오지 않는다. 동작과 UX만 참고한다.
- 키바인딩 기여는 없다. 웹뷰 안의 Enter·Esc 처리는 입력 UI의 일부다.

### 7.4 가정과 미결정

**가정(검증 전):**

- 웹뷰의 textarea에서 웹앱과 같은 수준으로 오버레이 힌트·IME 보류·실시간 오류가 동작한다.
- 에디터 안에 있으면 웹앱 탭보다 실제 반복 횟수가 는다(KR1로 확인).
- 공개 도메인 판정이 가능한 출처(저자 사후 70년, 미국은 1930년 이전 출판)로 명언 100개를 모을 수 있다. 명언 자체가 외울 동기가 되는지는 모른다.
- 복사한 웹앱 모듈이 웹뷰 환경(`Intl.Segmenter`, Worker)에서 웹앱과 같은 결과를 낸다. DOM·React 의존이 없음은 확인했다.
- 실시간 WPM이 속도 경쟁으로 흐르지 않고 "기억" 목표를 해치지 않는다. 사용자(2026-11-09)는 타이핑 기능이 있으니 실시간으로 보여 주는 쪽을 택했다. 관찰에서 힌트 없이 재현하기보다 속도만 올리는 행동이 보이면 기본값을 끔으로 바꾸는 것을 검토한다.

**미결정:**

- publisher ID. 라이선스는 MIT로 가정.
- 힌트 카드 모드(타이핑 없이 보고 가리기)를 1차에 넣을지. 웹앱 로직을 재사용하면 비용이 작아 1차 포함을 기본 가정으로 두되, 타이핑이 흔들리면 뺀다.
- `.txt`에서 본문을 고치면 카드 ID가 바뀌어 기록이 끊긴다. 허용할지, 위치 기반 ID로 완화할지.
- 명언 규모(처음 20개로 비용 추정 후 100개)와 해석 언어(한국어만인지 영어 설명도 넣는지).
- 성공 기준 수치(KR1의 60%, 4주)는 제안이다.

## 8. 출시

**1차(본인 설치용 `.vsix`):** 7.2의 1~9. 명언은 20개로 시작. 상대 기간으로 2~3주 작업, 그 뒤 4주 사용 관찰(KR1).

**2차(마켓플레이스 공개):** 7.2의 10, 명언 100개, 관찰에서 나온 수정. 공개 뒤 3개월 관찰(KR2·KR3).

**이후 후보:** 읽기 전용 에디터 탭에서 타이핑하는 모드(IME 제약으로 영어 전용 가능성), 사이드바 트리, Markdown 교재, 단축키.

**하지 않는 것:** 계정·서버·동기화·백업, 알림·보상·스트릭·통계 대시보드, 자동 암기 판정과 복습 일정, 웹앱 교재의 자동 공유(사용자가 파일을 복사한다), WPM 개인 최고 기록·추이 그래프·순위, vscode.dev 지원, 원격 측정.
