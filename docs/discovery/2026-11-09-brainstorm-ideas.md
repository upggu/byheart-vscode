# ByHeart for VS Code — 초기 탐색 아이디어

작성일: 2026-11-09 · 상태: 사용자 1차 답변 반영(6절). 1~5절은 답변 전 원안을 그대로 둔다 · 방법: `pm-product-discovery` / `brainstorm-ideas-new`

ByHeart 웹앱의 암기 방식을 VS Code 확장으로 옮기는 **신규 제품의 초기 탐색** 기록이다. 아래는 후보와 가정이며 결정된 요구사항이 아니다. 결정은 PRD에서 한다.

## 1. 기회 이해

### 1.1 사용자가 말한 것

- ByHeart 웹앱에서 학습하는 두 가지, **카드를 넘기며 보는 것**과 **타이핑으로 연습하는 것**을 VS Code 확장으로 구현한다.
- 교재 소스는 **사용자 로컬의 특정 폴더에 있는 문서**다.
- 기본 교재는 **저작권 문제 없는 주요 인사들의 명언**이다.
- [Warm Up — Typing Test](https://marketplace.visualstudio.com/items?itemName=jeusto.warm-up-typing-test)(`jeusto.warm-up-typing-test`)를 참고한다.
- 코드보다 문서를 먼저 만든다.

### 1.2 추정한 것 (검증 필요)

| 추정 | 근거 | 틀리면 달라지는 것 |
| --- | --- | --- |
| 첫 사용자는 본인 1명. 마켓플레이스 공개는 미정 | ByHeart PRD 5절과 동일한 출발 | 공개면 명언 출처 검증·라이선스·다국어가 1차 범위로 올라옴 |
| 사용 상황은 코딩 중 짧은 전환 시간(빌드·테스트 대기, 작업 시작 전)에 에디터를 떠나지 않고 1~3분 반복 | Warm Up의 "워밍업" 포지션, ByHeart의 "회사 PC 타이핑" 상황 | 긴 세션 중심이면 웹앱으로 충분하고 확장의 존재 이유가 약해짐 |
| 학습 기록은 기기 로컬. Settings Sync로 동기화하지 않음 | ByHeart 원칙(기기별 독립 기록) | 동기화를 원하면 저장 설계가 바뀜 |
| 영어 문장 암기가 1차. 한국어 해석은 보조 표시 | ByHeart와 같은 학습 대상 | 한국어 명언 타이핑이 1차면 IME 처리가 핵심 위험이 됨 |

### 1.3 ByHeart에서 가져올 핵심 동작

웹앱의 현재 합의(PRD 7절)와 코드 기준이다. 확장에서도 같은 규칙을 쓰는 것을 기본 가정으로 둔다.

| 동작 | 웹앱 근거 |
| --- | --- |
| 카드 하나 = 원본의 대사(turn) 한 줄. 여러 문장이어도 한 카드 | `src/lib/sentences.ts` |
| 짧은 힌트: 첫 단어 전체 + 둘째 단어 첫 글자(`We h`) | `src/lib/hints.ts` |
| 힌트로 암기: 회상 후 빈 영역 아무 데나 눌러(또는 Enter/Space) 정답 공개 | `src/components/FocusedPractice.tsx` |
| 타이핑으로 암기: 입력칸 하나에 같은 힌트를 반투명하게 겹침. 입력 중 틀린 글자만 빨갛게, 정답 단어를 아래에 작게 표시. IME 조합 중 표시 보류 | `src/lib/live-diff.ts`, `src/components/LiveTextarea.tsx` |
| 정답 확인: 입력칸 자리를 읽기 전용 비교 화면으로 전환. 엄격 비교(대소문자·구두점은 다른 색) | `src/lib/answer-diff.ts` |
| 미암기 표시·해제. 자동 암기 판정·평점·복습일 없음 | PRD 7.1 |
| 한 바퀴 완료 → `다음 챕터` 기본, 마지막은 `처음부터 반복` | PRD 7.1 |
| 설명용 turn(읽고 넘김), 해석 토글, `**굵게**`·`*이탤릭*` 강조 | PRD 7.4, `src/lib/emphasis.ts` |
| 콘텐츠 형식 `.byheart.json` (책 → 챕터 → turns) | `scripts/content.ts`, `data/chapters/` |

### 1.4 Warm Up에서 배울 것

마켓플레이스 페이지와 GitHub(`arhunsaday/warmup`, 기본 브랜치 `master`)의 README·`package.json`·폴더 구조만 확인했다. 소스 코드 본문은 읽지 않았다.

- **진입:** 상태바 항목, 단축키(`cmd+alt+p`), 커맨드 팔레트. 첫 키 입력으로 시작한다. 설정은 패널 툴바에서 바로 바꾼다.
- **두 가지 표시 면:** 테마를 따르는 웹뷰 패널, 그리고 **읽기 전용 에디터 탭**에서 흐린 원문이 타이핑할수록 밝아지는 모드. Vim 같은 확장이 에디터 입력을 소유하면 패널로 폴백한다.
- **입력 처리:** 실제 포커스된 input을 사용해 dead key·AltGr·IME 조합을 지원한다. ByHeart도 같은 원칙(IME 조합 중 보류)을 쓴다.
- **콘텐츠:** quotes 모드는 공개 도메인 출처만 사용한다. 선택 텍스트·현재 파일로 연습하는 명령이 있고 이 기록은 개인 기록에서 제외한다.
- **저장:** 결과와 개인 기록을 VS Code global state에 둔다.
- **구조:** `core`/`shared`/`src`(확장 호스트)/`webview`/`ui` 분리, tsup + Vite, Vitest, Biome.
- **라이선스:** GPL-3.0-or-later. 코드를 가져오면 우리 코드도 GPL이 된다. **동작과 UX만 참고하고 코드는 직접 작성**한다.

## 3. 상위 5개 후보

신규 제품 기준으로 **핵심 가치 전달 > 검증 속도 > 차별성** 순으로 가중했다.

### 1위. 한 카드 집중 연습 웹뷰 (D2 + D3 + E2)

- **이유:** 이것이 없으면 제품이 없다. 웹앱에서 검증된 화면·키보드 규칙을 그대로 옮기므로 설계 비용이 낮다.
- **검증할 가정:** 웹뷰 textarea에서 ByHeart 수준의 오버레이 힌트·IME 보류·실시간 오류 표시가 동작한다. 에디터를 떠나지 않는 것이 실제로 반복 횟수를 늘린다(웹앱 탭을 여는 것과 비교).
- **가장 싼 테스트:** 명언 5개를 하드코딩한 웹뷰 하나로 일주일 사용. 웹앱 대비 실제 사용 횟수를 본다.

### 2위. 로컬 폴더 교재 (P2 + E3)

- **이유:** 사용자가 명시한 요구이고, 명언을 넘어 제품이 계속 쓰일 이유다.
- **검증할 가정:** 사용자가 Markdown 규칙(제목 = 챕터, 단락 = 카드)을 지켜 작성하는 것이 부담이 아니다. 본문을 고쳤을 때 기록이 유지되길 기대하는지, 끊겨도 되는지.
- **가장 싼 테스트:** 실제 보유 문서 2~3개를 규칙에 맞춰 변환해 보고 어색한 지점을 기록한다. 코드 없이 가능.

### 3위. 기본 명언 교재 (P3 + D1)

- **이유:** 0 설정 시작과 공개 배포 안전성을 동시에 준다.
- **검증할 가정:** 공개 도메인 판정이 가능한 출처(저자 사후 70년 이상, 원문 확인 가능)를 100개 모을 수 있다. 한국어 해석은 자체 작성(기존 번역서는 저작권 있음). **명언이 영어책 대사만큼 외울 동기가 되는지**는 확인되지 않았다.
- **주의:** 명언은 오귀속이 흔하다. Wikiquote의 "Sourced" 항목처럼 1차 출처가 있는 것만 쓴다. 후보 인물 예: Marcus Aurelius, Seneca, 공자(논어 원문), Benjamin Franklin, Lincoln, Emerson, Thoreau, Mark Twain(1910 사망), Oscar Wilde(1900), Tolstoy(1910). 사망 70년이 지나지 않은 인물(예: Churchill 1965, Helen Keller 1968)은 제외. 미국은 출판 연도 기준(2026년 현재 1930년 이전 출판물)이 별도로 적용되므로 공개 배포 시 두 기준을 모두 확인한다.
- **가장 싼 테스트:** 출처 링크가 있는 명언 20개를 먼저 모아 본다. 20개에 걸리는 시간으로 100개 비용을 추정한다.

### 4위. 코어 공유 (E1)

- **이유:** 실시간 비교·힌트·강조는 웹앱에서 가장 많은 테스트(`tests/live-diff.test.ts` 등)를 가진 부분이다. 재구현은 낭비이고 규칙 불일치를 낳는다.
- **검증할 가정:** 해당 모듈의 브라우저 의존(Worker, `Intl.Segmenter`)이 웹뷰 환경에서도 그대로 동작한다. 추출 범위가 작다.
- **가장 싼 테스트:** 해당 파일들의 import 그래프를 그려 DOM·React 의존을 센다. 반나절.

### 5위. 상태바 2분 루프 + 선택 텍스트 연습 (P4 + E6)

- **이유:** Warm Up과 구별되는 "에디터 안에서 기억을 다진다"는 경험을 가장 빨리 체감하게 한다. 구현이 매우 작다.
- **검증할 가정:** 빌드 대기 같은 틈에 실제로 상태바를 누른다. 누르지 않는다면 "에디터 안"이라는 전제 자체가 약한 것이다.
- **가장 싼 테스트:** 1위 웹뷰에 상태바 진입만 붙여 하루 몇 번 누르는지 기록(로컬 카운터).

### 보류한 것

- **에디터 탭 타이핑(D4 + E5):** IME·다른 확장 충돌 위험이 크고 웹뷰로 핵심 가치는 전달된다. 2단계.

### 6.2 이름: `byheart`로 가능 (2026-11-09 확인)

- 마켓플레이스 검색 API로 `byheart`를 조회한 결과 **0건**이다. `memorize` 검색에는 Memorize, Memory Helper, Anki Sidebar 등이 있으나 이름이 겹치지 않는다.
- 마켓플레이스 규칙: `name`과 `displayName` 모두 전체에서 유일해야 하고, 한 번 쓴 이름은 삭제 후에도 영구 예약된다. `publisher` ID는 생성 후 변경 불가. 아이콘은 128px 이상 PNG, SVG 불가.
- 제안: `name: "byheart"`, `displayName: "ByHeart"`, 식별자 `<publisher>.byheart`. 폴더 이름 `byheart-vscode`는 저장소 이름으로만 쓴다. publisher ID는 사용자가 만들어야 하며 아직 없다.
- 주의: 미국의 분유 브랜드 ByHeart가 있다. 소프트웨어와 분류가 달라 마켓플레이스 등록에는 문제가 없을 것으로 보지만 법적 판단은 하지 않았다. 혼동을 피하려면 설명 첫 줄에 "memorize sentences by typing" 같은 문구를 넣는다.

### 6.3 교재 형식: 두 가지

**`.byheart.json`** — 웹앱의 `parseReviewDocument`(`src/review/model.ts`)와 같은 스키마를 그대로 받아들인다. 텍스트 챕터의 최소 파일은 다음과 같다. 음원 기반 파일(시각·SRT 지문 포함)도 그대로 열리며 시각은 무시한다.

```json
{
  "schemaVersion": 1,
  "documentId": "<UUID>",
  "revision": 0,
  "source": { "kind": "text", "basename": "Day 1" },
  "turns": [
    { "id": "<UUID>", "speaker": "", "text": "The only way out is through.",
      "translation": "유일한 출구는 통과하는 것이다.", "explanation": "- **way out**: 출구, 해결책" }
  ],
  "retiredTurnIds": []
}
```

필수는 `schemaVersion`·`documentId`·`revision`·`source.basename`·`turns[].id`·`turns[].speaker`(빈 문자열 가능)·`turns[].text`·`retiredTurnIds`다. 선택은 `kind`(`study`/`explanation`)·`section`·`translation`·`explanation`이다. 웹앱의 `books.json` 카탈로그는 확장에서 쓰지 않고, **폴더 하나 = 교재 하나, 파일 하나 = 챕터 하나**로 본다(웹앱 `content:sync` v2의 폴더 규칙과 같다). 교재 이름은 폴더 이름, 챕터 이름은 파일명에서 확장자를 뺀 것, 정렬은 숫자순.

**`.txt`** — 가장 낮은 진입 장벽. 규칙 후보: 빈 줄로 구분한 단락 하나 = 카드 하나, 단락 안의 줄바꿈은 그대로 유지. 첫 줄이 `# `로 시작하면 챕터 제목. 번역·해설은 없다(필요하면 AI로 `.byheart.json`으로 승격). 카드 ID는 파일 경로 + 본문 해시이므로 **본문을 고치면 기록이 끊긴다**. 이 제약을 가이드에 명시하고, 기록을 유지하고 싶으면 `.byheart.json`으로 쓰라고 안내한다.

**AI 작성 가이드** — 웹앱의 [AI 번역·해설 가이드](../../../byheart/docs/content/ai-translation-explanation-guide.md)처럼 복사해 붙이는 요청문을 README에 둔다. 입력은 txt나 임의 문서, 출력은 위 최소 스키마. UUID 생성, `text` 안 빈 줄 금지, 해설의 `- ` 불릿·`**굵게**`·`*이탤릭*`만 허용 같은 제약을 요청문에 포함한다.

### 6.4 저장 위치: `~/.byheart` 권장

VS Code 확장은 Node.js 확장 호스트에서 실행되므로 홈 디렉터리 아래 임의 폴더를 읽고 쓸 수 있다. 선택지는 둘이다.

| | `~/.byheart/` (권장) | `context.globalStorageUri` |
| --- | --- | --- |
| 위치 | `~/.byheart/books/<교재>/`, `~/.byheart/records/` | 예: `~/Library/Application Support/Code/User/globalStorage/<publisher>.byheart/` |
| 사용자가 파일을 넣기 | Finder·터미널로 바로 가능. 설정 없이 교재 추가 | 경로가 깊고 에디터마다 다름 |
| 에디터 간 공유 | VS Code·Insiders·Cursor가 같은 교재·기록을 봄 | 에디터 설치마다 분리 |
| 제거 시 | 남음(사용자 자산이므로 바람직) | VS Code 정리 동작은 확인하지 않음 |
| 위험 | 홈이 dotfiles 저장소나 클라우드 동기화 대상이면 기록이 따라감. 설정으로 경로 변경 허용 | 동일 |

권장안: 기본 `~/.byheart`(Windows는 `%USERPROFILE%\.byheart`), 설정 `byheart.folder`로 변경 가능. 기록은 교재와 분리해 `records/`에 교재·챕터별 JSON으로 두고 임시 파일 → rename으로 원자적으로 쓴다. 같은 PC의 두 창이 동시에 쓸 수 있으므로 revision 비교로 덮어쓰기를 막는다. 기본 명언 교재는 확장 패키지 안에 읽기 전용으로 두고 `~/.byheart`에 복사하지 않는다.

"개인 PC여야 한다"를 지키려면 두 가지를 `package.json`에 명시한다.

- `extensionKind: ["ui"]` — Remote-SSH·WSL·Dev Container·Codespaces에서도 확장이 **로컬 머신**에서 실행되어 로컬 `~/.byheart`를 쓴다. 지정하지 않으면 원격에서 실행될 수 있다.
- 브라우저 진입점(`browser` 필드) 없음 — vscode.dev 같은 웹 환경은 파일 시스템이 없으므로 지원하지 않는다.
- 네트워크 요청·원격 측정(telemetry) 없음을 README에 명시한다.

### 6.5 조정된 상위 후보

1. **타이핑 집중 연습 웹뷰** — 웹앱의 오버레이 힌트·실시간 오류·엄격 비교·Enter 진행을 그대로. 힌트 카드 모드는 같은 화면의 2순위 모드.
2. **`~/.byheart` 교재 폴더 + `.byheart.json`/`.txt` 어댑터** — 폴더 = 교재, 파일 = 챕터.
3. **기본 명언 교재** — 공개 배포이므로 출처 링크가 있는 공개 도메인 명언만. 한국어 해석은 자체 작성.
4. **byheart 코어 모듈 공유** — 비교·힌트·강조 로직.
5. **공개 배포 준비** — MIT 라이선스, 영문 README, publisher 생성, 아이콘, `.vsix` 로컬 설치로 먼저 검증.

제외: Markdown 어댑터, 웹앱 교재 자동 공유, 키바인딩 기여, 에디터 탭 타이핑(2단계 유지), 사이드바 트리(QuickPick 대체).
